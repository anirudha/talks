2026 reality check
Agents are everywhere.
And they're breaking everywhere.

Customer support. Code generation. Data pipelines. Production agents now sit on your hottest paths — and you've never had less visibility into a workload.

The core problem

Traditional APM treats an agent as a black box.

You see one span — POST /plan, 14 seconds, 200 OK. Inside that span: twelve LLM calls, four tools, three retries, and a hallucinated answer. Your dashboard says it succeeded. Your user disagrees.

What APM shows
A single fat span
Latency, throughput, error rate at the request boundary. Useful for services. Not enough for agents.
What's actually happening
Multi-step reasoning
Plan, call, read, call again, retry, branch. Sub-agents. Tools. State that doesn't fit in a single duration metric.
The gap
No semantic vocabulary
Without standard attributes for model, tokens, prompts, and tool calls, no tool can query across agents and frameworks.
The failure modes you can't see

Three ways your agent is already failing.

Failure 01
Hallucinates mid-task
Returns a confident, well-formatted, completely wrong answer. The trace looks healthy. The output is fiction.
Failure 02
Silently degrades
Quality drops 20% after a model swap or prompt edit. Latency unchanged. Error rate unchanged. You find out from a user a week later.
Failure 03
Drifts off the path
Same input, different tool sequence. Token cost doubles. The "right answer" arrives — by the wrong route — and you only notice on the AWS bill.

Stage 01 · Instrument

Three lines. Every span captured.

Drop the GenAI SDK in. Decorate your tools and agent functions with @observe. register() wires up OTel exporter and auto-instrumentation in one call. 

# pip install opensearch-genai-observability-sdk-py[anthropic]
from opensearch_genai_observability_sdk_py import register, observe, Op, enrich

register(
  endpoint="http://localhost:4318/v1/traces",
  service_name="travel-planner",
  auto_instrument=True,        # OpenAI · Anthropic · Bedrock · LangChain · 20+
)

@observe(op=Op.EXECUTE_TOOL)
def search_flights(origin: str, dest: str) -> list[dict]:
    enrich(session_id="travel-42")        # attach GenAI semconv attributes
    return flight_api.search(origin, dest)

The vocabulary, color-coded

Six span categories.

Every span maps to one of six operation types — derived from gen_ai.operation.name. Categories drive color, filtering, and aggregation across all three views.

▸ Agent ▸ LLM ▸ Tool ▸ Content ▸ Embeddings ▸ Retrieval

Agent = an autonomous run. LLM = a model invocation. Tool = an externally-callable function. Content = prompt & response payloads. Embeddings & Retrieval = the RAG hops most APMs miss entirely.

Ask any question, ad hoc

PPL across every agent span.

Token spend by model. Tool failure rate by agent. Sub-agent P99. Composed live in the same Dashboards surface as your trace tree. 

// Token spend by model and agent in the last hour
source = otel-v1-apm-span-*
| where isnotnull(attributes.gen_ai.request.model)
| stats
    sum(attributes.gen_ai.usage.input_tokens)  as in_tokens,
    sum(attributes.gen_ai.usage.output_tokens) as out_tokens,
    count()                                     as calls
  by attributes.gen_ai.agent.name, attributes.gen_ai.request.model
| eval est_cost_usd = (in_tokens * 0.000003) + (out_tokens * 0.000015)
| sort -est_cost_usd

— Pillar 02 · Quality —

Agent Health.

Traces tell you what happened. Health tells you whether the agent did the right thing — graded by an LLM judge against a Golden Path you define.

What Agent Health is

An evaluation framework for agents.

Built around LLM-judge trajectory comparison. You define the path. The judge grades whether the agent achieved the goal — even if it took a different route.

Test Cases
A scenario, written down
Initial prompt, expected outcomes, context. Versioned in the UI or in code.
Experiments
Batch runs across agents & models
Compare agent v1 vs v2. Compare Claude vs GPT vs Bedrock. Same test cases. Same judge.
LLM Judge
Pass/fail · accuracy · reasoning
A score with pass/fail status, accuracy 0–100%, reasoning, and improvement suggestions — every run.
Agent Health · Test Case

Define the path — once.

Initial prompt, expected outcomes, context. Run it across runs, traces, evaluations, conversation history, and the LLM judge — all in one view.
Agent Health · Experiment Run

Compare agents and models, side by side

Run summary across configurations — pass rate, tokens, cost, average duration. Performance vs. global best. Metrics over time. The CI loop for agents.
The judge in action

Golden Path — not exact match.

The judge doesn't require the agent to follow the trajectory step-for-step. It assesses whether the agent reasonably achieved the expected goals, even via alternative routes — and tells you why.
